 GOOGLE SIGN-IN + ACCOUNT-SETUP EMAIL - WHAT IS LEFT
====================================================================
Last updated: 2026-08-09

Short version
-------------
The feature is fully BUILT and TESTED. Nothing in the code is
outstanding. What remains is two credentials that can only be created
from your own Google account in a browser, which is why they are not
done already.

  1. A Google OAuth Client ID   -> makes the Google button live
  2. A Gmail App Password       -> sends the setup email for real
                                   (OPTIONAL - see section 5)

Until (1) is set, the "Continue with Google" button appears on the
sign-in and register pages as a greyed-out placeholder that says it
is not configured. Everything else in the app works normally.

 2. WHAT IS LEFT - YOUR PART
====================================================================

STEP 1 - Create the OAuth Client ID
-----------------------------------
  a. Go to  https://console.cloud.google.com/
  b. Create a project, or pick an existing one
  c. APIs & Services -> OAuth consent screen
       - User type: External
       - App name: (your app's name)
       - User support email + developer email: your address
       - Save and continue through the remaining steps
       (Only needed once per project. You can leave it in "Testing"
        mode; add your own Google address under "Test users" so you
        are allowed to sign in.)
  d. APIs & Services -> Credentials
       -> + Create credentials -> OAuth client ID
  e. Application type: Web application
  f. Authorised JavaScript origins -> + Add URI:

         http://localhost:3000

     Exactly that. No trailing slash. If you later host it somewhere,
     add that address here as well.
  g. Click Create, then copy the Client ID. It looks like:

         123456789012-abc...xyz.apps.googleusercontent.com

  IMPORTANT - do not confuse these three:
       Client ID      <- THIS is what is needed. Ends in
                         ".apps.googleusercontent.com"
       Client secret  <- NOT needed. Starts "GOCSPX-". Ignore it.
       API key        <- NOT needed. Starts "AIza". Wrong credential
                         type entirely; that is for data APIs.

  Cost: free. No billing account or card is required.


STEP 2 - Put it in the config
-----------------------------
  Open  server/.env  and set:

      GOOGLE_CLIENT_ID=123456789012-abc...xyz.apps.googleusercontent.com

  server/.env is gitignored, so this is never committed.


STEP 3 - Check it
-----------------
  From the project root:

      npm run check

  It will confirm the value is the right shape and warn you if you
  have pasted an API key or the client secret by mistake.


STEP 4 - Restart and try it
---------------------------
  Stop the server (Ctrl+C) and start it again:

      npm start

  Then open  http://localhost:3000/register
  The grey placeholder should now be a real Google button.

  Click it and sign in with a Google account. Expect:
    - you land on the dashboard, signed in
    - a new USER account exists for that Google address
    - the setup email appears IN THE SERVER CONSOLE (until step 5),
      containing a link like
        http://localhost:3000/account-setup?token=...
    - opening that link lets you set a password
    - after that, the same account can also sign in with email and
      password

  Note: this last click-through is the one part that cannot be
  verified for you, because it needs a real Google account and
  Google's consent screen in your own browser.

====================================================================
  npm run check      shows  [ OK ]  GOOGLE_CLIENT_ID

  In the browser, http://localhost:3000/api/auth/session should show

      "googleEnabled": true

  and the register page should show a live Google button rather than
  the grey placeholder.


====================================================================
 4. IF IT DOES NOT WORK
====================================================================

"Continue with Google" is still grey
    GOOGLE_CLIENT_ID is not set, or the server was not restarted
    after setting it. Run: npm run check

Google popup says "Error 400: redirect_uri_mismatch"
or "The given origin is not allowed"
    http://localhost:3000 is not in "Authorised JavaScript origins"
    for that OAuth client, or it was entered with a trailing slash or
    as 127.0.0.1. It must match exactly. Changes can take a few
    minutes to take effect on Google's side.

"That Google sign-in could not be verified" (401)
    The client ID in server/.env is not the one that issued the
    token - usually two different OAuth clients or two projects.

"Access blocked: app has not completed verification"
    The consent screen is in Testing mode and the Google account you
    are using is not listed. Add it under OAuth consent screen ->
    Test users.

Button appears but nothing happens on click
    An ad blocker or privacy extension is blocking
    accounts.google.com/gsi/client. Try a normal window with
    extensions disabled.


====================================================================
 5. OPTIONAL - SENDING REAL EMAIL
====================================================================
Not required. With MAIL_HOST left blank, the setup email is printed
to the server console, link included, which is enough to use and demo
the whole flow.

To send real mail through Gmail:

  a. The Google account must have 2-Step Verification switched on
  b. Google Account -> Security -> App passwords -> create one
     (16 characters; a normal account password will NOT work)
  c. In server/.env:

         MAIL_HOST=smtp.gmail.com
         MAIL_PORT=587
         MAIL_USER=your.address@gmail.com
         MAIL_PASSWORD=the16charapppassword
         MAIL_FROM=Inkwell <your.address@gmail.com>

  d. npm run check   then restart

Any other SMTP provider works too - only the four MAIL_* values
change.


====================================================================
 6. THINGS DELIBERATELY NOT DONE
====================================================================
Worth knowing these are choices, not oversights:

  - No client secret is stored. This app verifies Google ID tokens
    rather than running a server-side redirect flow, so there is
    nothing secret to keep.
  - No "sign in with Google" on the admin console specifically. Role
    is a property of the account, so a Google account promoted to
    ADMIN gets the admin console like any other.
  - Setup tokens are stored as plain values rather than hashes. This
    project stores passwords in plain text by explicit choice, so
    hashing the token beside them would be security theatre. The
    token is still long, random, single-use and short-lived.
  - Google users are not forced to set a password. The email invites
    them to; they can ignore it and keep using Google.
